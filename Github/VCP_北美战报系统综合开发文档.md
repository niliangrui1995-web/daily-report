## 一、系统概述

VCP Hunter 每日热点战报系统是一套全自动的 **AI 驱动产业链情报采集 → 审计清洗 → A股映射 → 技术面分析 → 战报生成** 的管线系统。

**核心能力**：通过 Google Search Grounding 联网搜索海外半导体/AI 产业链最新动态，经多层 AI 审计和推理后，自动映射到 A 股标的并生成可操作的每日战报。

## 八、各层详细说明

### 8.1 L1 情报采集（`collect_intelligence` + `gemini_search`）

- **并发控制**：`ThreadPoolExecutor(max_workers=3)`
- **风控措施**：每个请求前随机延迟 0.5-4 秒
- **重试策略**：最多 3 次，429/503 指数退避 + 随机抖动，401/403 直接熔断
- **应急机制**：当成功率 < 50% 时自动切换 Tavily API 补位（最多 5 条）
- **输出**：保存 `L1_原始数据_{时间}.json` 到输出目录

### 8.2 L1.5 审计清洗（`gemini_pro_audit`，audit_type="l1.5"）

- **任务一**：时效性验证（超出回溯窗口的删除）
- **任务二**：可信度打分（1-10 分，白名单信源加分）
- **任务三**：数据清洗（去主观、去分析师评级）
- **豁免规则**：十三太保股价数据即使看起来像噪声也保留
- **输出**：保存 `L1.5_审计_{时间}.md`
- **降级**：审计失败时使用 L1 原始数据

### 8.3 L2 A股映射（`generate_report`）

- **模型**：Claude Opus 4.6 Thinking
- **核心逻辑**：
  - 按赛道分组映射 A 股公司（每赛道 ≥ 3 家）
  - 弹性分级：🔥高弹性 / ⚡中弹性 / 💀纯概念
  - 十三太保信号推理（大涨→催化 / 暴跌→预警）
- **指挥官权限**：可在结尾输出 `SEARCH: [关键词]` 下达补充搜索（最多 5 条）
- **输出**：保存 `L2_映射_{时间}.md`

### 8.4 L3a 补充搜索 + L3.5 审计

- 解析 L2 输出中的 `SEARCH:` 指令
- 使用 Gemini Flash 执行搜索
- 搜索结果再经 Gemini Pro 审计（L3.5，无时效限制）
- 输出：保存 `L3.5_审计_{时间}.md`

### 8.5 L3b 本地通达信技术面（`l3_search_stock_prices`）

从 L2 映射中正则提取 A 股标的（公司名 + 6 位代码），读取本地通达信 `.day` 文件，计算：

| 指标                       | 说明                         |
| -------------------------- | ---------------------------- |
| 近 1 月 / 3 月涨跌幅       | 20 日 / 60 日收盘价变化      |
| 250 日区间分位             | 当前价位在年度区间中的位置   |
| 5 日/20 日量比             | 近期放量/缩量程度            |
| 布林带宽度（20日）         | < 10% 标注"极窄→蓄力中"      |
| 均线密集度（5/10/20/60日） | < 3% 标注"粘合→方向选择临界" |
| 距 60 日高回撤             | 最近高点的回撤幅度           |
| 近 5 日振幅均值            | < 3% 标注"波动压缩"          |
| MACD 柱状体 + 金叉/死叉    | EMA12/EMA26/DEA              |
| 10 日换手率均值            | 需要流通股本数据             |
| 20 日阳线占比              | 近 20 个交易日阳线比例       |

**财务数据**（来自 `VCPEngine.batch_get_finance_info`）：
- 总市值、总股本、流通股本
- 总资产、净资产、主营收入、净利润
- 经营现金流、每股净资产、股东人数

**输出**：保存 `L3_股价数据_{时间}.md`

### 8.6 L4 综合战报（`l4_risk_analysis`）

- **输入**：L1.5 审计情报 + L2 映射 + L3.5 审计补充 + L3b 技术面
- **输出结构**：
  1. 核心信号（≤ 5 条）
  2. 标的狙击表（表格，含短期爆发力 ⚡ 评级）
  3. 资金路径推演
  4. 今日操作建议（3-5 只）

> **⚠️ 警告：已全面废除内部的 `--schedule` / `while True` 死循环后台执行逻辑。**
> 为了避免“代码后台死循环”与“系统级任务”发生冲突导致的“同秒双开并发惩罚”，现在的标准调度唯一入口是 **Windows 计划任务 (Task Scheduler)**。

在 Windows 计划任务中设定：
- 交易日 09:00 / 12:30 / 14:20 自动触发 `python daily_report.py`
- 程序每次被唤醒后只执行一次 `[立即运行一次]` 的逻辑，执行完自动退出并释放系统句柄。

### 注意事项
- 单次执行依旧会判断当前时间窗口，进行诸如平时回溯 24h / 周一回溯 72h 等数据源剪裁逻辑。
- `HOLIDAYS_2026` 和非交易日的判断在最新的主流程中将直接执行 `sys.exit()`，免去 API 浪费。

        *   **0% 的检索精力**：跳过一切金融评级机构与 **CNBC 泛财经网站**。技术发布当周，搞金融的人根本没看懂图纸，绝对不浪费一丝算力给没有产业链常识的财经记者与所谓的大行分析师。
    *   **底层 Prompt 模板设想**：
        > "Gemini，今日 `{ticker}` 有重大技术/硬件发布！**警告：启动工程师模式，这绝不是一篇财经报道！**

        > 2. [30% 量化权重] 核心目标：强行从字皮书中剥离出纯工程参数：PCB板层数变更、单卡TDP满载功耗、网络接口带宽（如 NVLink 传输速率）、液冷 CDU 分配设计。

    *   **行动纲领**：在这个阶段，大模型必须撕掉“金融分析师”的伪装，彻底化身为“画图纸的电子工程师”。它只认材料、只认功耗热值、只认总线带宽。只有提取出这些最枯燥的工程数字，才能在 A 股准确无误地定位到到底是炒“高频高速覆铜板”、还是炒“多模态温控与快插连接器”。

### 阶段三：顶级 Alpha 降噪清洗与极客信息的客观组装 (Alpha Signal Filter)
此阶段是大模型过滤网络幻觉并在内存池进行双向比对的第一道阀门。清洗标准严格遵循数据驱动，拒绝“前景广阔”、“引发轰动”等一切脱离实际物理支撑和财务基础的主观废料。

1.  **纯情绪噪音的静默丢弃机制**：
    *   **判定标准**：若前端阶段一抓取的情报残片缺乏具体的规模数值、交期周数、良率百分比等清晰的物理与周期参数（例如通篇仅带“史诗级利好”、“下半年大爆发”等主观干瘪形容词），直接阻断通过。
    *   **量化预期**：此清洗动作要求将全天候抓取的无效投研废话滤除 85%，确保交由下端映射引擎的每一枚字符都是硬核事实。
2.  **绝对中立的强类型参数组装库 (JSON Schema Isolation)**：
    *   **判定标准**：系统不预设立场去裁决“什么是好消息、什么是坏消息”。
    *   **执行动作**：**【关键防投毒装甲】**为了彻底防止海外极客圈的反讽（Sarcasm）、假设性条件句（If/Rumor）对后端产生“语境投毒”，**绝对禁止第一层 AI 用自然语言向后传递情报**。一旦前端命中极客白名单的参数异动，强制大模型必须输出强类型验证的数据结构（如 JSON Schema：`{"Entity": "某厂", "Metric": "交期", "Value": "52周", "Confidence_Score": 0.9}`）。
    *   **代码级熔断**：一旦大模型判定原文带有 "If"、"Rumor" 或反讽语气，导致 `Confidence_Score` 过低，Python 隔离层会直接执行 `Nullify`（静默丢弃）拦截。通过验证的纯净 JSON，才会原封不动地被打上 `[🔗 底层链路高纯度事实]` 标签并输送给阶段四进行自主推理。

*(为确保理论框架极简且与架构图一致，原“财报电话实录防熔断降级预案”现转作代码端底层 try-catch 异常处理逻辑，不单独升格为业务大阶段)*

### 阶段四：基于定向公网感知与零样本推理 (Zero-Shot) 的 A股全息映射
根据系统铁律：**禁止任何先入为主的预设股票池，但必须赋予大模型全域的实时雷达视野**。如果在这一步彻底断网，大模型将受限于旧有的训练参数，产生严重的“刻舟求剑”幻觉（例如不知道某公司上个月刚突破了某种新材料的验证）。

因此，第二层 AI 必须具备**【基于第一层物理事件的定向公网检索权】+【本地财务数据运算权】**的双引擎架构。

**【动态推理与公网补货作业总纲】**
只要前端雷达探知到诸如“特定高频树脂交期阻断”、“某特殊液冷接头漏液率惩罚”等异动参数，第二阶段的大模型必须执行以下极其冷酷的连环逻辑：

1.  **公网实时概念补货 (Web-Grounded Entity Discovery)**：
    *   **运转逻辑**：模型接到“海外某型号电子布/特氟龙/干变缺货”指令后，**立刻被授权访问公网（联网搜索）**。它的搜索词不是去查利空利好，而是精准查询：“当前 A股市场，在 [该特定底层材料/设备设备] 领域，排名前列的上市公司有哪些？”、“谁最近发布了该领域的扩产定增或技术突破公告？”。
    *   **核心考核**：通过实时联网，把那些刚刚跨界成功、或刚刚突破技术封锁的最新 A股玩家矩阵，毫无遗漏地拖入候选池。彻底消灭因为历史预训练数据老化带来的认知盲点。
2.  **全维度实力排位与真伪甄别 (Strength Ranking & Falsification)**：
    *   **运转逻辑**：拿到公网搜回来的 A股玩家名单后，大模型必须进行“去伪存真”的交叉盘问。剔除那些只有“互动易嘴炮概念”但毫无实际产能或研发投入的蹭热点公司。
    *   **核心考核**：必须在最终报告中，清晰排列出这些对应公司在该细分领域的**实力梯队、市占率生态位**（谁是一供，谁是备用二供，谁是纯概念）。
3.  **彻底抛弃本地财报：直接公网模糊定性测算 (Fuzzy Qualitative Web-Search)**：
    *   **运转逻辑**：把上述经过公网清洗的、排名靠前的真实业务公司，直接**通过定向公网检索索取其最新公布的官方年度/季度财报（或业绩预告）核心业务占比概况**。在此环节，**无需考虑任何本地财务数据运算，也绝对禁止让大模型去算百分比小数点的精确弹性**。
    *   **核心考核**：大模型的任务必须严格止步于“模糊的正确”：从公网财报中粗略评估该项业务在公司总营收中的分量（是“九牛一毛的试验线”还是“半壁江山的核心利润源”）。如果海外缺口引发涨价，该内资工厂面临的是【高弹性】、【中弹性】还是【纯概念炒作】？只需要给出大方向和量级，保留 A 股最核心的情绪博弈朦胧美，最终的精确胜率判断与开仓动作甚至无需大模型介入，将由交易员人工接管。
4.  **绝不妥协的结构化战报输出**：
    *   系统最终将这套当场组合出来的逻辑链合并打包。报告必须包含：**起因（海外哪家寡头出了什么物理事件） $\rightarrow$ 补货（公网搜出 A股实力排名前三的对应玩家） $\rightarrow$ 验算（他们的真实财报营收占比与涨价弹性）**。
    *   为随后的量化射击提供“没有感情、只有数据与算力交叉验证”的开火诸元。

### 阶段五：系统级抗风控（Anti-Ban）与无人值守守护底座
在多模型、跨中转反代的高并发请求下，为彻底根除系统因 IP 被封禁、API 抛出 403/429 熔断而导致的战报停发，底座必须硬装甲化：

1.  **绝不双开：单实例全局计划任务托管**：
    *   彻底废除 Python 代码内部的 `while True` 定时死循环守护。将全域唤醒权 100% 交接给 **Windows Task Scheduler (计划任务)**。
    *   严格限定每天 `09:00` (早盘前扫雷) 与 `14:20` (尾盘截面定池) 两次交互唤醒，根除后台脚本与系统任务互博带来的“同秒重放攻击(Replay Attack)”。
2.  **发包指纹池伪装 (User-Agent Spoofing)**：
    *   拦截官方 SDK（Gemini / Anthropic）默认发出的 `python-requests` 机器裸奔指纹。在所有请求头中强制注入高可信度的 `Chrome/124.0.0.0 Safari/537.36` 浏览器指纹，直接绕过 Cloudflare 等网关的初级检测。
3.  **微秒级并发防抖与退让算法 (Jitter & Exponential Backoff)**：
    *   压制瞬间并发峰值：主动将并行搜索的线程并发上限控制在 `GEMINI_CONCURRENCY = 2`。
    *   每次起跑前强制注入 `time.sleep(random.uniform(1.0, 6.0))` 随机秒数抖动，模拟真人的低频点击频率，将 API QPS（每秒请求数）强行压平，极大保护了反代 IP 的长期存活寿命。

```text
你是 VCP Hunter L4 层——最终战报生成器，深谙 A 股投机规律。

⚠️ 当前时间：{当前北京时间，精确到分钟}。
过期旧闻（如 2025 年或更早）标注为【过期信息】或直接忽略。

你将收到四层数据：
1. L1.5 审计后情报（已经过 Pro 可信度打分+时效验证+主观清洗）
2. L2 映射
3. L3.5 审计后补充搜索结果（已经过 Pro 可信度打分+主观清洗）
4. L3 数据：通达信 250 日 K 线 + 8项技术指标 + 财务数据

【战报结构】：

## 一、核心信号（≤5 条）
从 Gemini 联网搜索信息中提炼最值得关注的产业链信号。
标注【信源|日期】和置信度（🟢高/🟡中/🔴低）。

## 二、标的狙击表（重点！每个细分行业最多 3 只）
| 标的 | 代码 | 总市值 | 最新价 | 近 3 月 | 250 日分位 | 量能 | 弹性 | 短期爆发力 | 风控 |

短期爆发力判断（核心关注！）：
- ⚡⚡⚡ 极强：市值轻+低位+缩量蓄势+催化剂明确
- ⚡⚡ 较强：有催化但已涨一波
- ⚡ 一般：大盘股或已高位

风控评级：基于 250 日 K 线 + 技术指标自行判断 🟢/🟡/🔴

## 三、资金路径推演
海外事件 → 产业传导 → A 股标的排列

## 四、今日操作建议
3-5 只最值得关注的标的 + 理由

基于 L3 真实数据，不要编造。字数不限，写多少算多少。

【铁律】：尽量简洁！每条结论一句话说清楚，不要废话套话，不要重复已知信息。表格优于文字。
```

## 北美战报调度规则

### daily_report.py 任务调度（Windows 计划任务触发）

| 触发时间 | 扫描模式               | 回溯窗口        | 数据来源               |
| -------- | ---------------------- | --------------- | ---------------------- |
| 09:30    | `full`（全量）         | 24h（周一 72h） | 19 条查询全量搜索      |
| 12:30    | `x_only`（X 突发专扫） | 3.5h            | 仅 X 平台大 V 突发消息 |
| 14:20    | `x_only`（X 突发专扫） | 2h              | 仅 X 平台大 V 突发消息 |

> `get_run_config()` 根据当前小时自动判断模式：≤9 点全量，12 点 X 专扫 3.5h，≥14 点 X 专扫 2h。

### VCPHunter 终端战报刷新规则

| 触发时间 | 刷新模式      | 行为                                   | 序号颜色         |
| -------- | ------------- | -------------------------------------- | ---------------- |
| 09:30    | `full`        | 清空表格，加载最新战报全部股票         | 默认白色         |
| 13:00    | `incremental` | 仅追加新增股票到表格末尾，不覆盖已有行 | 🟠 橙色 `#FF9F0A` |
| 14:35    | `incremental` | 仅追加新增股票到表格末尾，不覆盖已有行 | 🔵 青色 `#32D7E0` |

> 增量追加用两种颜色区分来源时间，方便一眼识别哪些是新增的。
